# 3단계 구현 후 면접/학습 개념 정리

3단계는 Redis 스타일 응답 포맷과 명령어 파서를 구현하는 단계이다. 핵심은 사용자 입력 문자열을 안정적으로 해석하고, 실행 결과를 일관된 프로토콜 형태로 출력하는 것이다.

## 1. 핵심 개념

- 파싱은 문자열 입력을 명령어와 인자로 나누는 과정이다.
- 실행 로직은 파싱 결과를 받아 저장소에 명령을 전달한다.
- 응답 포맷은 명령 실행 결과를 사용자에게 보여주는 규칙이다.
- 파싱, 실행, 응답 생성을 분리하면 테스트와 유지보수가 쉬워진다.

## 2. 파싱에서 신경 쓸 점

- 명령어 이름은 대소문자를 구분하지 않는다.
- 공백 없는 값과 큰따옴표로 감싼 값을 모두 지원한다.
- 인자 개수 오류와 알 수 없는 명령 오류를 구분한다.
- 파싱 실패와 명령 실행 실패는 다른 에러로 처리한다.

예시:

```text
SET name alice
SET message "hello world"
GET name
```

## 3. Redis 스타일 응답

대표 응답:

- 성공 단순 문자열: `OK`
- 없는 값: `(nil)`
- 정수 응답: `(integer) N`
- 문자열 값: `"value"`
- 에러: `(error) ...`

응답 생성 함수를 분리하면 명령어 구현에서 문자열 포맷이 흩어지는 것을 막을 수 있다.

## 4. 구현 후 설명할 수 있어야 하는 것

- 파서와 실행기를 분리하는 이유는 무엇인가?
- 큰따옴표 문자열 파싱에서 어떤 문제가 생길 수 있는가?
- 에러 응답을 한 곳에서 관리하면 어떤 장점이 있는가?
- Redis 스타일 응답과 일반 Python 반환값은 어떻게 다른가?

## 5. 면접 질문 예시

- CLI 명령어 파서를 설계할 때 어떤 예외 상황을 고려해야 하나요?
