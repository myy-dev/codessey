# 8단계 구현 후 면접/학습 개념 정리

8단계는 보너스 과제를 기본 저장소와 독립된 학습 모듈로 확장하는 단계이다. 핵심은 String 저장소의 책임은 유지하면서 자료구조와 메시징 학습 범위를 완성하는 것이다.

## 1. 핵심 개념

- 보너스 과제는 기본 기능을 망가뜨리지 않는 선에서 적용한다.
- 동적 배열은 최소 힙 구현에 이미 통합되어 있다.
- 이진 트리 개념은 힙의 완전 이진 트리 배열 표현으로 연결된다.
- 스택, 큐, 덱은 `STACK_QUEUE_DEQUE.md`에 정리하고 트리 순회와 메시지 버퍼에 연결한다.
- 일반 이진 트리와 BST는 `data_structures`의 독립 모듈로 구현한다.
- Pub/Sub는 저장소와 분리된 공유 인메모리 버스로 구현한다.

## 2. 통합 가능한 보너스

### 동적 배열

- 최소 힙 내부 저장소로 사용한다.
- capacity 확장과 amortized O(1)을 설명할 수 있다.

### 이진 트리

- 힙을 완전 이진 트리의 배열 표현으로 설명한다.
- 부모/자식 인덱스 계산을 복습한다.
- 일반 이진 트리에서 전위, 중위, 후위, 레벨 순회를 구현한다.

### 연결 리스트 재활용

- LRU 구현에 사용한다.
- Pub/Sub의 구독자별 FIFO 메시지 버퍼로 재사용한다.

## 3. 독립 모듈로 구현한 보너스

### 스택/큐/덱

- `STACK_QUEUE_DEQUE.md`에서 개념과 사용 사례를 정리한다.
- CLI history, 메시지 큐, 작업 큐 같은 예시와 연결할 수 있다.

### BST

- 기본 Redis String 기능에는 직접 필요하지 않다.
- 삽입, 검색, 삭제와 중위 순회 정렬 결과를 독립 모듈에서 구현한다.

### Pub/Sub

- 네트워크 통신 없이 단일 프로세스 학습 모델로 제한한다.
- `PUBLISH`, `SUBSCRIBE` 명령과 구독자별 메시지 큐를 구현한다.

## 4. 구현 후 설명할 수 있어야 하는 것

- 어떤 보너스는 기본 구현에 통합하고, 어떤 보너스는 분리했는가?
- 기능 확장이 기존 설계를 복잡하게 만들 때 어떻게 판단하는가?
- Pub/Sub가 일반 key-value 저장소와 다른 점은 무엇인가?
- BST가 현재 핵심 기능에 적합하지 않은 이유는 무엇인가?
