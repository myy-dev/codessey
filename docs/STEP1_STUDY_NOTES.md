# 1단계 구현 후 면접/학습 개념 정리

이 문서는 `plan.md`의 1단계인 동적 배열, 이중 연결 리스트, 해시맵, 최소 힙 구현을 마친 뒤 복습할 개념을 정리한다.

목표는 단순히 코드가 동작하는지 확인하는 것이 아니라, 각 자료구조를 왜 선택했는지, 어떤 비용이 발생하는지, Redis 구현에서 어떻게 연결되는지 설명할 수 있게 되는 것이다.

## 1. 공통으로 설명할 수 있어야 하는 개념

### 시간복잡도와 공간복잡도

반드시 설명할 수 있어야 하는 항목:

- `O(1)`, `O(log n)`, `O(n)`의 차이
- 평균 시간복잡도와 최악 시간복잡도의 차이
- 자료구조 선택이 연산 비용에 미치는 영향
- 빠른 연산을 위해 추가 메모리를 쓰는 trade-off

면접 질문 예시:

- 시간복잡도와 공간복잡도는 무엇인가요?
- `O(1)`이라고 해서 항상 빠른가요?
- 평균적으로 빠르지만 최악의 경우 느려지는 자료구조 예시는 무엇인가요?

### 불변식

자료구조 구현에서는 항상 유지되어야 하는 조건이 있다. 이를 불변식이라고 한다.

예시:

- 동적 배열: `0 <= size <= capacity`
- 이중 연결 리스트: `node.next.prev == node`, `node.prev.next == node`
- 해시맵: 같은 키는 하나의 엔트리만 가진다.
- 최소 힙: 부모 노드는 자식 노드보다 작거나 같다.

면접 질문 예시:

- 자료구조를 직접 구현할 때 버그를 줄이기 위해 어떤 조건을 확인하나요?
- linked list에서 삭제 연산 후 반드시 맞아야 하는 포인터 관계는 무엇인가요?

## 2. 동적 배열

### 핵심 개념

Python의 `list`는 이미 동적 배열이지만, 이 과제에서는 내부 동작 원리를 학습하기 위해 직접 구현한다.

동적 배열은 다음 상태를 가진다.

- `size`: 실제 저장된 원소 수
- `capacity`: 현재 확보한 저장 공간 크기
- `items`: 내부 저장 공간

배열이 꽉 차면 더 큰 배열을 만들고 기존 원소를 복사한다.

```text
capacity 4에서 append 중 가득 참
-> capacity 8 배열 생성
-> 기존 원소 복사
-> 새 원소 저장
```

### 왜 비효율적이지 않은가

resize가 발생하는 순간은 `O(n)`이다. 하지만 매번 resize하지 않고 보통 capacity를 2배로 늘리기 때문에 append의 평균 비용은 `O(1)`로 볼 수 있다. 이를 amortized O(1), 또는 분할 상환 O(1)이라고 한다.

### 구현 후 설명할 수 있어야 하는 것

- 왜 capacity를 1씩 늘리지 않는가?
- 왜 2배 확장을 쓰는가?
- resize 순간의 비용은 얼마인가?
- append 평균 시간복잡도는 왜 `O(1)`인가?
- linked list와 비교했을 때 장단점은 무엇인가?

### 면접 질문 예시

- Python list는 내부적으로 어떤 자료구조에 가까운가요?
- 동적 배열에서 append는 항상 `O(1)`인가요?
- capacity를 2배로 늘리는 이유는 무엇인가요?
- 배열과 linked list 중 힙 구현에 더 적합한 것은 무엇이고, 왜 그런가요?

## 3. 이중 연결 리스트

### 핵심 개념

이중 연결 리스트는 각 노드가 이전 노드와 다음 노드를 모두 참조하는 구조이다.

노드 구조:

```text
prev <- node(data) -> next
```

이 프로젝트에서는 LRU 구현에 사용한다.

- head: 가장 최근 사용한 키
- tail: 가장 오래 사용하지 않은 키

### Redis 구현과의 연결

LRU eviction을 효율적으로 구현하려면 다음 연산이 빨라야 한다.

- 키가 사용되면 front로 이동
- 오래된 키를 tail에서 제거
- 특정 키가 삭제되면 해당 노드를 바로 제거

이중 연결 리스트만 사용하면 특정 키의 노드를 찾는 데 `O(n)`이 걸린다. 따라서 해시맵에 `key -> node`를 함께 저장해 특정 노드 삭제와 이동을 `O(1)`에 가깝게 만든다.

### 구현 후 설명할 수 있어야 하는 것

- 단일 연결 리스트와 이중 연결 리스트의 차이
- 특정 노드를 `O(1)`에 삭제하려면 왜 `prev`가 필요한가?
- LRU에서 head와 tail이 각각 무엇을 의미하는가?
- linked list만으로 LRU를 만들면 어떤 문제가 있는가?
- 해시맵과 linked list를 함께 쓰면 어떤 장점이 있는가?

### 면접 질문 예시

- LRU Cache를 `O(1)`로 구현하려면 어떤 자료구조가 필요한가요?
- linked list에서 노드 삭제 시 어떤 포인터를 갱신해야 하나요?
- 이중 연결 리스트의 단점은 무엇인가요?
- 배열 대신 linked list를 쓰면 좋은 경우는 언제인가요?

## 4. 해시맵

### 핵심 개념

해시맵은 키를 해시 함수에 넣어 버킷 인덱스를 계산하고, 해당 위치에 값을 저장하는 자료구조이다.

기본 흐름:

```text
hash(key) -> bucket index -> bucket에서 key 검색 -> value 저장/조회
```

이 프로젝트에서는 Python `dict`를 대체하는 핵심 저장소로 사용한다.

사용 위치:

- 데이터 저장: `key -> value`
- TTL 저장: `key -> expire_at`
- LRU 노드 참조: `key -> node`

### 충돌과 체이닝

서로 다른 키가 같은 버킷 인덱스를 가질 수 있다. 이를 해시 충돌이라고 한다.

체이닝 방식은 같은 버킷 안에 여러 엔트리를 연결해서 충돌을 해결한다.

```text
bucket[3] -> (key1, value1) -> (key2, value2)
```

### 로드 팩터와 리사이징

로드 팩터는 버킷 수 대비 저장된 엔트리 수를 의미한다.

```text
load_factor = size / bucket_count
```

로드 팩터가 너무 커지면 충돌이 많아져 조회 성능이 떨어진다. 이 프로젝트에서는 0.75를 초과하면 버킷 수를 2배로 늘리고 모든 키를 다시 배치한다.

### 구현 후 설명할 수 있어야 하는 것

- 해시 함수가 하는 일
- 해시 충돌이 발생하는 이유
- 체이닝 방식과 open addressing 방식의 차이
- 로드 팩터가 높아지면 왜 성능이 나빠지는가?
- 해시맵 조회가 평균 `O(1)`이지만 최악 `O(n)`인 이유
- 리사이징 때 왜 rehash가 필요한가?

### 면접 질문 예시

- 해시맵은 어떻게 평균 `O(1)` 조회를 제공하나요?
- 해시 충돌은 어떻게 해결할 수 있나요?
- 좋은 해시 함수의 조건은 무엇인가요?
- 로드 팩터가 무엇이고 왜 중요한가요?
- Python dict를 쓰면 쉬운데 왜 직접 구현해보는 것이 의미 있나요?

## 5. 최소 힙

### 핵심 개념

최소 힙은 항상 가장 작은 값이 root에 있는 완전 이진 트리 기반 자료구조이다.

이 프로젝트에서는 TTL 만료 시간이 가장 빠른 키를 찾기 위해 사용한다.

저장 형태:

```text
(expire_at, key)
```

가장 빠르게 만료될 키가 heap의 root에 위치한다.

### 배열로 표현하는 완전 이진 트리

힙은 트리처럼 이해하지만 실제 구현은 배열이 적합하다.

인덱스 관계:

```text
parent = (i - 1) // 2
left_child = i * 2 + 1
right_child = i * 2 + 2
```

이 때문에 힙은 linked list보다 배열 기반 구현이 자연스럽다.

### 주요 연산

- `push`: 마지막에 넣고 위로 올린다. `O(log n)`
- `pop`: root를 제거하고 마지막 원소를 root로 옮긴 뒤 아래로 내린다. `O(log n)`
- `peek`: root만 확인한다. `O(1)`

### TTL lazy deletion

같은 키에 `EXPIRE`가 여러 번 호출되면 힙에는 오래된 만료 기록이 남을 수 있다.

해결 방법:

- `expires` 해시맵에는 최신 expire_at만 저장한다.
- 힙에서 꺼낸 `(expire_at, key)`가 최신 값과 다르면 무시한다.

이 방식을 lazy deletion이라고 한다.

### 구현 후 설명할 수 있어야 하는 것

- 힙과 이진 탐색 트리의 차이
- 최소 힙에서 root가 의미하는 것
- `push`, `pop`이 왜 `O(log n)`인가?
- 힙을 배열로 구현하는 이유
- TTL 관리에서 왜 힙이 적합한가?
- lazy deletion을 쓰는 이유와 단점

## 6. 1단계 자료구조 간 연결 관계

각 자료구조는 따로 존재하는 것이 아니라 Redis 기능 구현을 위해 함께 사용된다.

```text
HashMap
  - key -> value
  - key -> expire_at
  - key -> LRU node

DoublyLinkedList
  - LRU 사용 순서 관리
  - head: 최근 사용
  - tail: 오래 미사용

MinHeap
  - 가장 빠른 TTL 만료 후보 관리
  - (expire_at, key)

DynamicArray
  - MinHeap 내부 저장소
  - capacity 확장 학습
```

설명할 수 있어야 하는 핵심 문장:

> 해시맵은 빠른 키 조회를 담당하고, 이중 연결 리스트는 사용 순서를 담당하며, 최소 힙은 만료 시간을 담당한다. 동적 배열은 힙의 인덱스 기반 저장소로 사용된다.

## 8. 짧은 면접 답변 템플릿

### Q. LRU Cache를 어떻게 구현하나요?

해시맵과 이중 연결 리스트를 함께 사용합니다. 해시맵은 key로 노드를 `O(1)`에 찾기 위해 쓰고, 이중 연결 리스트는 사용 순서를 관리하기 위해 씁니다. 조회나 저장이 발생하면 해당 노드를 head로 이동시키고, 용량을 초과하면 tail의 노드를 제거합니다.

### Q. 해시맵은 왜 평균적으로 빠른가요?

키를 해시 함수로 버킷 인덱스에 바로 매핑하기 때문에 전체 데이터를 순회하지 않아도 됩니다. 충돌이 적고 로드 팩터가 적절히 유지되면 조회, 삽입, 삭제가 평균 `O(1)`입니다. 충돌이 심하면 최악의 경우 `O(n)`까지 나빠질 수 있습니다.

### Q. 동적 배열 append는 왜 평균 O(1)인가요?

배열이 꽉 찼을 때 resize는 `O(n)`이지만, capacity를 보통 2배로 늘리기 때문에 resize가 자주 발생하지 않습니다. 여러 번의 append에 복사 비용이 분산되어 append 1회 평균 비용은 `O(1)`로 볼 수 있습니다.

### Q. TTL 구현에 왜 최소 힙을 쓰나요?

TTL에서 중요한 것은 가장 먼저 만료될 키를 빠르게 찾는 것입니다. 최소 힙은 가장 작은 만료 시간을 root에서 `O(1)`에 확인할 수 있고, 삽입과 제거도 `O(log n)`에 처리할 수 있어 만료 관리에 적합합니다.

### Q. 힙과 BST는 어떻게 다른가요?

힙은 부모와 자식 사이의 우선순위 관계만 보장하며 root에서 최소값이나 최대값을 빠르게 찾는 데 적합합니다. BST는 왼쪽 서브트리와 오른쪽 서브트리의 정렬 관계를 보장해서 탐색과 정렬 순회에 적합합니다. 힙은 전체 정렬 상태를 보장하지 않습니다.
