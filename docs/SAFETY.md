# 안전 모드와 전송 범위

## 기본 ON

`--safe-mode`는 기본으로 켜져 있다. Git에서 읽은 문자열을 마스킹한 뒤 파일·줄·문자
제한을 적용한다. PEM 개인키 블록을 먼저 마스킹하여 전송 제한이 블록을 자르는 경우를
방지한다. 파일 이름과 이전 이름에도 같은 마스킹을 적용한다.

- 알려진 OpenAI/GitHub/Slack/AWS 키, JWT, Bearer/Basic 인증 문자열
- 이메일, URL의 사용자명·비밀번호, password/token/secret/API key 형태의 할당문
- PEM 개인키 블록
- 최대 10개 파일, diff 헤더를 포함한 총 200줄, diff 최대 20,000자

한 파일의 diff가 제한을 모두 사용하면 이후 파일은 생략된다. 결과에 전체 파일 수,
전송 파일 수, 제외/생략 파일 수와 잘림 여부를 표시한다. 잘림 안내가 있으면 사람은
누락된 변경을 확인해야 한다. `--staged`로 검토 범위를 나눌 수 있다.

## 항상 적용되는 보호

`--no-safe-mode`에서도 실행에 사용하는 실제 API 키는 본문과 터미널 출력에서 제거한다.
`.env*`, 개인키 파일, 알려진 자격증명 파일, 심볼릭 링크는 두 모드 모두 제외한다.
ANSI 제어문자·양방향 텍스트 제어문자를 제거한다. Git 외부 diff/textconv 및 fsmonitor
실행을 비활성화하며 Git 인덱스를 변경하지 않는다.

안전 모드 OFF는 패턴 마스킹과 10파일/200줄 제한을 해제한다. 무제한 입력은 허용하지
않으며 모드 공통으로 Git 명령 출력 2MB, 전체 diff 200,000자 상한이 있다.
정규표현식은 임의 형식의 비밀, 인코딩된 비밀, 헤더가 없는 개인키 일부를 모두 찾을 수
없다. `--preview`로 실제 전송할 메시지를 확인하고 전송 가능한 변경만 선택한다.

```bash
python main.py pr --safe-mode --preview
python main.py commit --staged --safe-mode
```

`--preview`는 요청 본문에 들어갈 메시지를 표시하고 API를 호출하지 않는다.
API 키는 인증 헤더로만 OpenAI에 전달한다. 생성 요청은
`https://api.openai.com/v1/chat/completions`로 전송하며 임의 엔드포인트 설정은 받지 않는다.
자동 재시도는 0회이고 오류 시 원본 응답 본문이나 키를 출력하지 않는다.

## 재현 가능한 ON/OFF 비교

실제 비밀이 없는 임시 Git 저장소에 가짜 API 키·이메일·비밀번호, 일반 파일 13개,
자격증명 파일 1개를 만들고 다음을 실행했다. 외부 API 호출은 0회다.

```bash
python -m scripts.demo_safety
```

결과 원문: [safety-comparison.json](examples/safety-comparison.json).

| 확인 항목 | OFF | ON |
| --- | --- | --- |
| 일반 파일 전송 수 | 13 | 10 |
| 자격증명 파일 제외 | 1 | 1 |
| 파일 제한으로 생략 | 0 | 3 |
| 가짜 API 키·이메일·비밀번호 | 보임 | 마스킹 |
| 자격증명 파일 내용 | 제외 | 제외 |
| 잘림 안내 | false | true |
| API 호출 | 0 | 0 |

별도 자동 테스트는 300줄 diff, 30,000자 한 줄, 230줄 개인키 블록,
이메일이 포함된 파일 이름, 외부 파일 심볼릭 링크도 검증한다.
