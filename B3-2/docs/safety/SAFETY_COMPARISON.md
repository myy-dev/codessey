# 안전 모드 ON/OFF 마스킹 비교

## 비교 대상과 방법

- 임시 Git 저장소의 미커밋 예시 파일 `welcome_email.py` 1개 사용
- 환영 이메일 데이터 생성 및 수신자·표시 이름 입력 검증 코드 20줄
- 마스킹 대상: 시연용 `sender@example.test`, `DEMO_ONLY_PASSWORD`
- 동일한 파일을 유지한 채 `--safe-mode`와 `--no-safe-mode`로 PR 초안 각각 생성
- 공통 설정: `gpt-4.1-mini`, temperature `0.2`, max-tokens `1200`, convention `team`
- 실제 OpenAI API 모드별 1회 호출, 총 2회 성공
- 비교 후 임시 파일·저장소 삭제, 예시 파일 커밋 없음

## 입력 비교

| 항목            | ON           | OFF                   |
| --------------- | ------------ | --------------------- |
| 발신자 이메일   | `[REDACTED]` | `sender@example.test` |
| SMTP 비밀번호   | `[REDACTED]` | `DEMO_ONLY_PASSWORD`  |
| 전송 파일 수    | 1개          | 1개                   |
| 전송 diff 줄 수 | 26줄         | 26줄                  |
| 변경 생략       | 없음         | 없음                  |

- OFF diff에 마스킹을 적용한 값과 ON diff의 완전 일치 확인
- 파일 수·줄 수·문자 수 제한 미도달로 마스킹 효과만 비교
- 구현 내용: [안전 정책](SAFETY.md)
- 실제 전송한 diff 전체: [ON/OFF diff 원문](SAFETY_DIFF.md)

## 생성 결과 비교

| 항목                                  | ON                               | OFF                              |
| ------------------------------------- | -------------------------------- | -------------------------------- |
| PR 제목                               | feat: 환영 이메일 생성 기능 추가 | feat: 환영 이메일 생성 기능 추가 |
| 제목 길이                             | 21자                             | 21자                             |
| Why 불릿                              | 2개                              | 2개                              |
| What 불릿                             | 3개                              | 3개                              |
| How to Test 불릿                      | 3개                              | 3개                              |
| 형식 보정                             | 없음                             | 없음                             |
| 시연용 이메일·비밀번호 값의 결과 노출 | 없음                             | 없음                             |

- 공통 내용: 환영 이메일 데이터 생성, SMTP 설정, 입력값 검증 설명
- ON: 함수 추가와 기본 설정 중심의 요약
- OFF: 모듈 추가와 입력값 검증 중심의 요약
- 제목 일치, 본문 표현 차이 외 핵심 변경 설명의 큰 차이 미관찰
- OFF의 결과에 값이 없어도 API 입력에는 시연용 값 그대로 전달
- 두 결과 모두 How to Test에 `미실행:` 표시, 실제 테스트 수행 주장 없음

### ON 생성 원문

```text
feat: 환영 이메일 생성 기능 추가

변경 요약
- 새로운 환영 이메일 생성 함수 build_welcome_email 추가
- 기본 SMTP 설정과 발신자 이메일을 포함하는 설정 딕셔너리 추가

## Why
- 사용자에게 환영 이메일을 보내는 기능이 필요함
- 이메일 생성 시 필수 입력값 검증을 통해 안정성 확보

## What
- MAIL_SETTINGS 딕셔너리에 SMTP 호스트, 발신자 이메일, 비밀번호 설정 추가
- build_welcome_email 함수는 수신자 이메일과 표시 이름을 받아 이메일 내용을 딕셔너리로 반환
- 입력값 검증을 통해 이메일 주소와 표시 이름의 유효성 검사 수행

## How to Test
- 미실행: 유효한 이메일과 표시 이름을 사용해 build_welcome_email 함수 호출 후 반환값 확인
- 미실행: 이메일 주소가 없거나 '@' 문자가 없는 경우 예외 발생 확인
- 미실행: 표시 이름이 공백인 경우 예외 발생 확인
```

### OFF 생성 원문

```text
feat: 환영 이메일 생성 기능 추가

변경 요약
- 환영 이메일 생성용 새 모듈 welcome_email.py 추가
- 이메일 수신자와 표시 이름 유효성 검사 기능 포함

## Why
- 사용자 가입 후 환영 이메일을 보내기 위한 기본 기능 필요
- 이메일 주소와 표시 이름의 유효성을 사전에 검증하여 오류 방지

## What
- MAIL_SETTINGS 딕셔너리에 SMTP 설정과 발신자 이메일 포함
- build_welcome_email 함수로 이메일 제목과 본문을 포함한 이메일 데이터 생성
- 입력값 검증을 통해 잘못된 이메일 주소나 빈 표시 이름 처리

## How to Test
- 미실행: 유효한 이메일과 표시 이름으로 build_welcome_email 호출 시 올바른 딕셔너리 반환 확인
- 미실행: 이메일 주소가 없거나 '@' 문자가 없을 때 ValueError 발생 확인
- 미실행: 표시 이름이 빈 문자열일 때 ValueError 발생 확인
```

## 비교 결론

- 민감정보에 해당하는 시연용 값의 마스킹 및 핵심 변경 요약 유지 확인
- 안전 모드의 효과: 생성 문구 변경보다 API에 전달되는 민감정보 값의 제거
- 모드별 1회 실험 범위에서 생성 결과의 큰 차이 미관찰
