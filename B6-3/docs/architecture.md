# 서비스 구조와 동작

## 계층별 역할

| 계층 | 역할 | 주요 파일 |
| --- | --- | --- |
| 앱 구성 | 시작 처리, 미들웨어, 라우터 등록, 전역 예외 처리 | [main.py](../main.py) |
| 공통 기반 | 환경 변수, DB 엔진·세션·테이블, 예외 정의 | [core/](../core/) |
| 인증·인가 | 세션 사용자 조회, 로그인 검사, CSRF, OAuth 통신 | [auth/](../auth/) |
| 라우터 | 요청값 수신, 서비스 호출, 화면 응답·리다이렉트 | [routers/](../routers/) |
| 서비스 | 입력값·소유권·상태 변경 검증 | [services/](../services/) |
| 저장소 | SQLAlchemy 데이터 조회·변경 | [repositories/](../repositories/) |
| 모델 | 테이블, 외래 키, 양방향 연관관계 | [models/](../models/) |
| 화면 | 공통 컨텍스트, Jinja2 SSR, 반응형 스타일 | [core/ui.py](../core/ui.py), [templates/](../templates/), [static/](../static/) |

## 요청 처리 흐름

1. 미들웨어와 의존성을 통한 세션 복원·사용자 확인·DB 세션 준비
2. 라우터의 요청값 수신과 서비스 호출
3. 서비스의 규칙 검증과 저장소를 통한 DB 조회·변경
4. Jinja2 화면으로 결과 표시 또는 변경 성공 후 HTTP 303으로 조회 화면 이동

- 요청 종료 시 `get_db` 의존성을 통한 DB 세션 정리
- 전역 예외 처리기를 통한 오류 응답·로그인 화면 이동

## 인증과 접근 제어

- `auth/`의 의존성에서 로그인 여부 검사
- 서비스에서 프로젝트·할 일의 소유권 검사

처리 상세는 [인증 문서](authentication.md), 경로별 정책은 [경로 문서](routes.md) 참고

## 데이터와 연관관계

`User → Project → Task`의 양방향 1:N 관계 두 개 구성

컬럼·제약 조건·삭제 정책은 [ERD 문서](erd.md) 참고

## 상태 변경

- [TaskService](../services/task_service.py)에서 대기·진행 중·완료 사이의 모든 변경 허용과 상태 값·중복 변경 검증
- 저장소의 이전 상태·소유권 재검사를 통한 동시 변경 충돌 처리
